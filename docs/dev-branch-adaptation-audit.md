# Adapting the dev application to Laravel

Compared against local `dev` at `11aa748fbc63ec1e4fda4399f39e5dfaaabc1f3e` on 2026-11-14. Its separate worktree was clean and was not modified. The design baseline is the existing React pages, routes, Fluent UI components and SCSS. Laravel is a change of data source and enforcement boundary, not a replacement page design.

The user subsequently approved a different grouping for **Laravel settings only**: separate sidebar links for Departments, Users, and Roles & Permissions. Departments now has its own list and creation/group-mapping dialogs. Users opens the existing user table without the combined tabs. Roles & Permissions lists the four built-in roles, their descriptions and View permissions actions; Agent/Admin actions open the existing permissions editor, Requester is fixed/read-only and Super Admin has a fixed organization-wide summary. SharePoint mode retains its original combined Users & Roles page. The new routes are `/settings/departments`, `/settings/users` and `/settings/roles-permissions`; the prior backend users-and-roles link remains an alias to the role list.

Department role settings govern how those roles behave within each department; changing a user's role/status can affect their other memberships, so confirmations explicitly say this. Removing a direct department assignment does not remove membership supplied by an Entra group. Super Admins remain scoped to their organization, not other customers.

## Validation and deployment boundaries

Backend tests cover permission checks outside React, original settings API contracts, schema metadata, directory resolution, assignment writes, source/type/date persistence and assigned-ticket initial status. Frontend adapter tests exercise the original page interfaces. Existing dev regression tests and the production SPFx build are also run. Source-level reuse and successful builds do not constitute a browser pixel comparison or live Azure SQL integration test.

Results for this pass: 56 backend tests (289 assertions), 12 Laravel adapter tests, formatting and the production build passed. The package is version 1.1.4.0; lint warnings remain. The broader legacy selection initially had nine failures; the new department-context dependency was added to the settings test harness, fixing the introduced failure. The remaining eight failures were reproduced against the unchanged dev source using a read-only source overlay, with identical failure names and errors. They include stale role-behavior assertions and missing mocks for IconButton, react-router-dom, UserDetailsPanel and AttachmentFiles. Those existing failures were not disguised by changing assertions or weakening authorization. Private comparison logs are under ignored `backend/storage/app/private/`.

The existing local SQLite database was backed up and upgraded with the data-preserving maintenance tool for the additional nullable fields. The original test migration remains the schema source; no incremental migration was added for this test rebuild. Azure was not updated. The next deployment requires the new Laravel image and SPFx package together, followed by the already agreed controlled Azure test-schema rebuild. Do not use the failing Azure SQL `migrate:fresh` wipe.

The navigation follow-up adds no migrations or backend permission changes. Its route, role-list/view, department creation, group-mapping edit, failed-read protection and legacy settings/adapter checks passed (14 tests). The updated SPFx package version is 1.1.5.0.

## Knowledge Base and comment follow-up

Knowledge Base and Need Help now reuse their existing screens through Laravel article endpoints. Articles are scoped to organization and department, with published/draft visibility, management permissions, classification relationships, bulk operations, ticket-to-draft conversion and server-side HTML sanitizing. Comment deletion is restricted to the author within the first ten minutes, enforced by Laravel as well as the interface.

The existing test migration now includes `knowledge_articles`. The local SQLite upgrade created a backup and preserved existing records; all 24 tables passed foreign-key checks. No new migration file, Azure schema change, application build or deployment was performed for this follow-up. Validation: 64 backend tests (340 assertions), 14 adapter tests, the self-service guide test, targeted settings/role tests, PHP formatting and local database connectivity passed.

## Application-owned departments and delegated user management

Requester is now displayed as User; its stored identifier remains compatible. The Add Users dialog renders directory results and selected people in tables, with independent role selectors initialized from the active tab. Manage users is an aggregated backend permission for adding staff, role/status changes and membership removal. API capability metadata hides unauthorized actions, protects self/Super Admin access and prevents global role/status edits to staff with unmanaged department memberships. Entra groups no longer supply department membership; staff are grouped within DeskPilot. Existing saved permission settings need an explicit Super Admin grant for the new Manage users action. No database migration or application build is required for these changes.
